# Detailed Attribute-To-Tool Workflow Matrix

Date: 2026-05-13

Planner window: 4-8 May

Decision gate:

> Do all selected attributes have at least one plausible workflow?

Answer:

> Yes. Every selected `GroundTruth.csv` attribute has at least one plausible workflow. The workflows are not equally mature: some are vision-led, some need 2D-to-3D projection and point-cloud geometry, and some need trajectory context or reduced-scope pilots.

## Agent Roles Used In The Matrix

| Agent | Role | Repository / tool support |
| --- | --- | --- |
| Scene Understanding Agent | Reads the panorama and describes road context, lane layout, roadside, markings, access, and visibility. | `panoramic-road-safety-describer`; VLM/manual prompt fallback. |
| Object Detection Agent | Finds physical objects such as barriers, poles, trees, walls, signs, lighting, and access features. | GroundingDINO local repo or HF GroundingDINO. |
| 2D-to-3D Projection Agent | Converts image bboxes or boundary points into LAS point indices. | `projection-dataflow-router`, `scripts/bbox_to_points.py`. |
| Point-Cloud Geometry Agent | Segments road/ground, clusters points, measures distances/widths/heights. | `pointcloud-multistep-processor`, `segment_road_cloud.py`, Open3D/SciPy helpers. |
| Trajectory Geometry Agent | Uses pose/GPS/heading sequence to estimate curvature and segment-level context. | `lookup_dataset_filtered_corrected.csv`, trajectory files, new curvature script needed. |
| Attribute Reasoning Agent | Converts evidence into iRAP numeric code using codebook and rules. | Codebook from `images-labeling-coding.xlsx`; rule templates. |
| Final Synthesizer Agent | Resolves conflicts, attaches evidence, and outputs final row-level codes. | Planned global orchestrator. |

## Attributes Requiring 3D Or Geometry

| Requirement | Attributes |
| --- | --- |
| Must use 2D-to-3D projection and LAS for robust result | Lane width; roadside severity driver/passenger distance. |
| Should use 3D measurement when available, but can start visually | Paved shoulder driver/passenger side; median width; sidewalk separation width. |
| Uses trajectory geometry rather than point cloud | Curvature; sight distance support. |
| Mostly visual / object detection | Area type, street lighting, service road, delineation, roadside object class, property access points. |

## Immediate Implementation Priorities

1. Build a row-level orchestrator that runs agents in this order: resolve data, scene understanding, detection, projection/geometry where needed, iRAP reasoning, comparison.
2. Cache projected LAS-to-image pixels per image/LAS pair so distance and width workflows do not reproject full clouds repeatedly.
3. Implement lane/shoulder boundary measurement pilots because these are the clearest missing 3D workflows.
4. Improve roadside severity final selection: candidate recall is good, but final selected object needs risk hierarchy plus distance evidence.
5. Keep sight distance as reduced scope until a repeatable visibility metric exists.
