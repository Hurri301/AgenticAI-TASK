## Pilot Results

### Roadside Object Detection

Output:

`artifacts/pilot_2026-05-13/roadside_object_detection_pilot_comparison.csv`

Summary:

- 5 images
- 10 side-specific object predictions
- GPU detector ran successfully
- Top-detection object-code accuracy against GT: `30%`

Interpretation:

The detector is operational, but using the top confidence detection alone is not enough. The roadside pipeline needs calibrated candidate selection, risk ranking, and possibly side-specific prompt tuning before batch use.

### Curvature

Output:

`artifacts/pilot_2026-05-13/curvature_pilot_results.csv`

Summary:

- 5 GT rows tested
- 1 row needs lookup fallback
- Accuracy on the simple heading-window heuristic: `20%`

Interpretation:

The curvature component is implemented as a smoke test, but it is not reliable yet. The next version should estimate curve radius or heading change over a road-distance window rather than a fixed frame window.

## Attributes Needing Fallback Or Reduced Scope

| Attribute group | Need |
| --- | --- |
| Visual attributes: area type, lighting, service road, median, delineation, shoulders, sidewalk, access points | Need standardized prompt/codebook templates and a manual/vision pilot on the 5 manifest rows. |
| Number of lanes | Needs a lane-count workflow; use manual/vision count as fallback for now. |
| Lane width | Needs lane/road boundary measurement; use reduced scope until boundary detection is available. |
| Sight distance | Recommend reduced scope / pilot-only status because reliable visibility estimation needs stronger assumptions. |
| Curvature | Needs improved trajectory geometry and lookup repair for `08_N114`. |
| Roadside severity object | Needs ranking/prompt calibration before scaling; manual review fallback for ambiguous detections. |
| Roadside severity distance | Component exists, but 5-row batch distance should wait until selected object bboxes are calibrated. |
